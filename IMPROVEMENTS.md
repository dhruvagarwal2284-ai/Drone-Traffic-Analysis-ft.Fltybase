# Improvement report — final polish pass (23 Sep 2026)

An audit of the whole project (code, published numbers, dashboard, docs) to get it
interview-ready. Two earlier revisions (EXPLAINER.md) had already fixed the big modelling
problems: wrong detector classes and a fragmenting tracker. This pass looked for what those
revisions left behind. Every finding below was reproduced before being fixed, and every
fix was re-run and checked.

### B. Pipeline bugs (data correctness)

| # | Bug | Evidence | Effect |
|---|---|---|---|
| B1 | **Class leak inside tracks.** `trajectories.build()` forward-filled each frame's raw detector label, so a road user's class could change from frame to frame. | 18 of 602 tracks carried two classes, e.g. track 164 = 454 `autorickshaw` frames + 4 `motorcycle` frames. | A phantom **`motorcycle` class (105 samples)** appeared in the speed table and histograms beside `two_wheeler`. ## 2. What was changed

### Code

| File | Change |
|---|---|
| `src/trajectories.py` | Each track now carries **one class, its majority vote** (with a deterministic tie-break), instead of forward-filled per-frame labels. **(B1)** |
| `src/insights.py` | Contraflow events are stamped at the first contraflow sample and located at the mean of the contraflow samples. Stop events use the first stationary sample and the stationary position. **(B2)** |
| `src/run_analysis.py` | New `presence_share_pct` (A6) and `conflicts.two_wheeler_involved` (B3) keys, so both headline figures come from the pipeline. All anomalies are exported (was the first 40). The plate calculation receives the calibrated height. |
| `src/attributes.py` | `plate_requirements(calibrated_height_m=…)` rescales the GSD to the run's own calibration. **(A7)** |
| `src/build_dashboard.py` | CLI: `--dest`, `--clip-base`. The demo dashboard is built with clips resolved beside it. The duplicate import was removed. |
| `make_package.sh` | Builds `demo/dashboard.html` with `--clip-base ""` instead of copying the out/ build. |
| `tests/test_pipeline_fixes.py` | **New.** Regression tests for B1 and B2, each verified to **fail on the pre-fix code** and pass after. |

### Dashboard (`src/dashboard_template.html`)

- A proper HTML5 document with UTF-8 and a viewport tag (A1).
- A sticky section nav and a light/dark toggle that is remembered across visits (A9).
- **"Three findings" cards** near the top: altitude correction, signal-vs-uncontrolled, and two-wheeler safety share. Every number in them is live from the payload.
- **"See the worst interactions"**: the six evidence clips, inline, with grade, measure and classes (A5).
- **"How the numbers got better"**: a v0 → v1 → v2 comparison table. The v2 column is live from the payload.
- The fleet table shows share **by track** *and* **by presence**, with a caption on when to quote each (A3, A6).
- The map is framed on the traffic, with the six busiest movements labelled without overlaps (A4).
- The pipeline and limits text are rewritten for the current system (A2).
- One class vocabulary everywhere (`pedestrian`, `auto-rickshaw`, `↔`), and auto-rickshaws get their own colour (A8).
- The anomaly table has kind filters and scrolls, so all 75 events are reachable (A9).
- Each chart renders inside its own `try`, so one bad field cannot blank the page (A9).

## 4. What is still open (and would be the next steps)

1. **OSM match rate at 82.6%.** Detections on verges and footpaths fall outside the 20 m
   road buffer. The fix is to filter detections to plausible road surface before
   map-matching. It is a detection-side problem, not a tracking one.
2. **Pedestrian recall.** Short-lived pedestrian detections never confirm as tracks
   (`min_hits = 3`). This is a detector limit.
3. **Appearance re-identification** across the tree occlusion. `detect.py --embed` already
   emits a 20-float HSV + size vector as a hook for it.
4. **Longer analysis window.** Conflict rates come from one 120 s window. Running
   several windows would give confidence intervals.
5. **Engineering hygiene.** `config.yaml` is documentation only (nothing parses it), and
   `run_geo.py` / `run_attrs.py` hard-code the video name and t0. A single `pipeline.py`
   entry point that reads the config would remove about seven manual steps.
